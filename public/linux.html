This ZIP contains the Python app and launchers. Install Python 3.10 or newer first. The first launch needs internet to install dependencies. Extract the ZIP into a folder you can write to.

Start on Windows

  1. Install Python with the Python launcher enabled, then extract the ZIP.
  2. Open DRONEmapper-Desktop-0.6.4\linux-node and double-click Start-DRONEmapper.cmd. The shared source folder is named linux-node on all three systems.
  3. The launcher installs the node dependencies and opens 127.0.0.1:8790. Leave its terminal running.

For Bluetooth, choose System Bluetooth. Wi-Fi capture needs Wireshark with Npcap, raw 802.11 capture support and a compatible monitor-mode driver. Optional HackRF/RTL-SDR tools and USB drivers are installed separately; see the receiver guide.

Start on macOS

  1. Install Python, extract the ZIP and open Terminal in DRONEmapper-Desktop-0.6.4.
  2. Run bash linux-node/Start-DRONEmapper.command.
  3. The launcher installs dependencies and opens the local radar. Allow Terminal/Python Bluetooth access when macOS asks, then choose System Bluetooth.

Wi-Fi capture needs Wireshark, its ChmodBPF capture-permission setup and a compatible monitor interface. With Homebrew, optional SDR tools can be installed with brew install hackrf or brew install rtl-sdr. Full receiver requirements are in the desktop setup guide.

Windows/macOS support includes the dashboard, radar, account pairing and receiver integrations. The shared code has automated checks; native Windows/macOS hardware reception still needs field testing.

Start on Debian or Ubuntu

  1. Download and extract the ZIP. Open a terminal inside DRONEmapper-Desktop-0.6.4.
  2. Plug in a dedicated USB Wi-Fi adapter. Run iw dev to find its interface name. Keep your normal Internet adapter separate.
  3. Run bash linux-node/setup-debian.sh YOUR_DEDICATED_USB_INTERFACE, replacing the final word with that interface name.
  4. Setup requests sudo to install the receiver tools, configure capture permissions and create a monitor interface. It starts the dashboard at 127.0.0.1:8790. Leave the terminal running.

Setup starts Wi-Fi on channel 6 and selects HackRF. In Radio settings, choose your attached receivers; set SDR to Off if you do not use one. Stop listening before changing receivers, save, then start again. After setup, bash linux-node/run-local.sh starts the node with your saved settings.

Linux: Bluetooth or SDR without Wi-Fi

Install Python 3.10+ and its virtual-environment package. From the extracted folder:

python3 -m venv .venv-node
. .venv-node/bin/activate
pip install './linux-node[all]'
dronemapper-node serve

Select your Bluetooth controller and/or SDR in the dashboard. Install your distribution’s hackrf or rtl-sdr package for SDR reception. A PortaPack must be in its HackRF / RF USB mode.

If passive Bluetooth reports that BlueZ experimental support is required, run bash linux-node/enable-passive-ble.sh from the extracted folder. It backs up the host configuration and briefly restarts Bluetooth. The node retries automatically.

Linux: add SDR protocol decoding

Stop the node, then run these commands from the extracted folder:

bash linux-node/install-decoders-debian.sh
bash linux-node/run-local.sh

The installer builds readsb with HackRF and RTL-SDR support and installs the DJI decoding dependencies. In Radio settings, select a receiver and choose ADS-B or, for HackRF, DJI DroneID. Save and start listening. Wi-Fi and Bluetooth keep running alongside the SDR.

ADS-B receives 1090 MHz aircraft broadcasts. DJI mode captures and decodes the researched OcuSync 2.0 waveform on a selected channel, with gaps during processing. The ZIP includes docs/sdr-decoders.md for setup, supported formats and recording review.

On Windows/macOS, use the desktop receiver guide to install compatible decoder tools; the Debian installer above is Linux-only.

ESP32 / CYD serial receiver

  1. Connect a board running Remote ID-capable Marauder firmware with a USB data cable.
  2. Open USB serial receiver → Refresh ports, choose its port, Marauder and 115200, then Connect receiver.
  3. Start Wi-Fi → Sniffers → Remote ID Scan on the board. Reports appear in the desktop list and signal radar.

Stock Marauder CSV reports stay local because their GPS fix age is unavailable. Receivers sending complete timestamped Remote ID JSON can contribute through your normal sharing setting. The download includes docs/serial-receivers.md with both formats. No separate MQTT bridge is needed.

Linux: optional channel hopping

After monitor setup, run sudo python3 linux-node/channel-hop.py --interface dmmon0 in a second terminal. The helper visits supported channels, prioritizes channel 6 and restores the original channel when stopped. Keep the dashboard running as your normal user. One dedicated radio can stay fixed while another hops. Marauder manages its own hopping.

Connect your account

  1. Click Connect to DRONEmapper → Continue in browser.
  2. Sign in and approve the matching code. Your account password stays in the website.
  3. Return to Station location & sharing, choose the reports to contribute, and save. Sharing starts off.

Remote ID uses broadcast-reported aircraft positions. Camera-link sharing needs station coordinates and sends only a rounded 0.01° receiver area. Radio MACs and network names remain local. Choose a public display name or remain Anonymous through your account.

What the receivers show

  • Wi-Fi: Remote ID beacons and NAN messages, plus possible WiFi CAM and Tello links. Up to four dedicated monitor interfaces, on fixed channels or with the optional Linux hopping helper.
  • Bluetooth: Remote ID advertisements through the system Bluetooth API on Windows/macOS, or a selected BlueZ controller on Linux. macOS uses discovery scanning and local device UUIDs rather than radio MAC addresses.
  • HackRF or RTL-SDR: spectrum measurements or ADS-B protocol decoding. HackRF also supports DJI DroneID capture/decode cycles and recording review. Ordinary aircraft remain local; fresh decoded drone positions have a separate sharing choice.
  • USB serial: external ESP32/CYD Remote ID receivers using Marauder CSV or the documented raw Remote ID JSON format.
  • MQTT: optional input from an authorized receiver broker using the documented Remote ID format.

The clickable radar’s Signals view shows strength; dot angles are layout only. Positions uses fresh reported GPS relative to the station, with selectable viewing ranges from 100 m to 500 km. A larger antenna must match the frequency and receiver; it does not supply a bearing or decode additional protocols by itself.

Carbyne domain activity

Desktop 0.6.4 can recognize Carbyne, Fusus and Dedrone domain lookups on your local network. Under Radio settings → Local network discovery, choose a LAN interface and enable Listen for Carbyne, Fusus and Dedrone domain lookups. Save, start listening, and open Local service activity. Entries show receive times and platform links. Website visits can match too; these local observations do not identify drones or create map points. Setup and research ↗

Local network discovery

The desktop node includes an optional LAN receiver. Stop listening, choose an interface under Radio settings → Local network discovery, save and start. With Wireshark capture access, it passively recognizes ARP senders with reviewed Verkada MAC allocations. Entries show the manufacturer, MAC and receive time in Local network devices. They remain local, with model unknown; they do not create radar positions or map points.

Device reference includes the wired CM42 camera and GW31-E gateway with official links. Physical reception of these models has not been verified. Setup and research.

Hardware and updates

Linux monitor reception has been tested with a Panda RT5572, spectrum reception with a PortaPack in HackRF USB mode, and passive Bluetooth reception with a Panda-branded USB adapter (7392:c611). All three receivers ran together. RTL-SDR reception still needs hardware testing. A real Remote ID transmitter is still needed to verify decoded positions over the air. The ADS-B test opened HackRF successfully but received no fresh aircraft positions. DJI decoding passed published-recording tests, including conversion to HackRF’s 20 Msps signed 8-bit format; live DJI reception still needs a supported aircraft test.

To stop, press Ctrl+C in the terminal; restart with the same launcher. To update, stop the node, extract the new release and run its launcher. If updating files in place, pass --update to refresh dependencies. Debian/Ubuntu users can run bash linux-node/run-local.sh from the new folder. Pairing and sharing settings live in your private user-state directory and are preserved. Keep one node process running per state directory.

Robot signals

Bluetooth can also recognize a documented CyberDog advertisement pattern. It appears as a possible robot dog in the live list and Signals radar. Enable Share approximate robot signal areas separately to contribute a rounded station area. A match has no robot coordinates and does not authenticate its identity. Physical CyberDog reception still needs field testing.
